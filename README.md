# 問答アトラス(mondo-atlas)

Perseus Digital Library のプラトン全集 36 篇を、**ステファヌス番号という一本の背骨**で
通して可視化する。

プラトンの著作は「対話篇」と呼ばれるが、対話の濃さは篇によって桁違いに違う。
同じ物差しを全篇に当てて、**どの篇のどこで問答が起き、どこで独白に変わるか**を見せる。

**①全集の俯瞰 / ②問答の呼吸 / ③語の地層 / ④文体の指紋 / ⑤和訳 / ⑥読む**。

## L0 でいちばん大事だった発見

**Perseus の話者マークアップ `<said>` は、29/36 篇で印刷面の話者記号 `<label>` と件数が
厳密に一致する。**つまり `<said>` は OCT の紙面に印刷された `ΣΩ.` `ΚΡ.` の写しである。

だから **OCT が話者記号を印刷しない篇 —— 語り直し型の対話篇 —— では使えない。**
『国家』は 88,000 語を超えながら `<said>` が 278 件・話者 1 名しかない。
『パルメニデス』の 1,072 件は**すべて枠の語り手に付いており、その内部に
「とソクラテスが言った」を含む**。

埋め合わせは本文の中にある。語り直し型では話者交替が**叙述内の発話動詞**
(`ἦν δʼ ἐγώ`「と私は言った」/ `ἦ δʼ ὅς`「と彼は言った」)で標示される。
分布は `<label>` ときれいに相補的で、『国家』では 2,106 件。

**『国家』の問答は 278 回ではなく、約 2,000 回起きている。**

詳細は [docs/L0-findings.md](docs/L0-findings.md)。

## L2 でいちばん大事だった発見

**対照を置いたら目玉が落ちた。**

発話交替を本文だけから検出する器を書き、上演型 27 篇を半分に割って
14 篇で閾値を決め、13 篇で報告した。境界の位置を当てる F1 は **0.567**、
無作為の 0.043 に対して 13 倍である。**ここで止めていれば成功と書いていた。**

置いた対照は「文の切れ目をすべて境界とする」という手がかり無しの素通しで、その F1 は **0.569**。
負けている。偶然の 13 倍は文の切れ目が効いているだけで、
定型応答も呼びかけも何ひとつ足していなかった。

そこで、図が実際に見せるもの —— 節ごとの**濃さ** —— の物差しで測り直した。
相関は手がかり **0.756** / 素通し 0.713 / **節の語数だけ −0.021**。
語数の交絡には 13/13 篇で勝った。

> **交替の位置は当てられない。濃さは当てられる。**

詳細は [docs/L2-findings.md](docs/L2-findings.md)。

## L3 でいちばん大事だった発見

**通説がひとつ、データに出なかった。**

構想では目玉を「『国家』は第 1 巻だけが問答で、以降は独白に化ける」に置いていた。
巻ごとに測ると、第 1 巻は 24.5 回/千語で、第 7 巻の 29.6 回/千語より**低い**。
交替の回数で見るかぎり第 1 巻に断絶は無い。目玉の文言を差し替えた。

代わりにデータが選んだのは**メネクセノス**である —— 冒頭が対話(約 45)、
長い葬送演説の間が平坦(約 18)、末尾で対話が戻る(約 48)。
「対話が独白になる瞬間」がいちばんはっきり出る。
『饗宴』では各人の演説が 0 に近く、ソクラテスとディオティマの問答で 40.5 に跳ねる。

詳細は [docs/L3-findings.md](docs/L3-findings.md)。

## L4 でいちばん大事だった発見

**屈折語は語幹では数えられない。しかも両方向に壊れる。**

語幹 `ειδ` で拾うと、目当ての **εἶδος(411 件)より εἰδέναι「知ること」(244)・
εἰδώς(87)・εἴδωλον(26)のほうが多い**。逆に語幹 `πολι` は πόλις の斜格
πόλεως(281)・πόλει(391)を丸ごと取りこぼす。
**片側だけ直すと、二つの誤りが打ち消し合って総数がそれらしく見える。**

さらにアクセントを畳むと区別が消える —— νόμος(法)と νομός(牧草地)、
ἀγαθῶν(善の)と **Ἀγάθων(『饗宴』の登場人物)**、ἐπιστημῶν と ἐπιστήμων(形容詞)。

そこで語形の**採否台帳**を人が書き、コードは台帳を当てるだけにした。
台帳は `etl/audit_words.py` が両方向で検算する。

その結果ひとつ言えること: **「イデア論」の語は ἰδέα ではない。**
εἶδος 411 件に対し ἰδέα は 98 件で、**4.2 倍の差**がある。

詳細は [docs/L4-findings.md](docs/L4-findings.md)。

## L5 でいちばん大事だった発見

**測る前に予測を 4 つ書いて記録し、それから測った。4 つとも成立した。**

通説で「後期」とされる 6 篇(ソピステス・政治家・ピレボス・ティマイオス・クリティアス・法律)は、
**ヒアトゥス率で 36 篇中の 1・3・4・5・6・7 位**を占めた。
後期 0.170 / その他 0.337、置換検定 **p = 0.00005**、篇の長さとの相関は −0.193(交絡ではない)。
**通説の群は当てはめに一度も使わず、照合にだけ使った。**

第二の物差し(καθάπερ / ὥσπερ の使い分け)も同じことを言う。
二軸の相関 −0.896 は、**後期群を除いた 30 篇でも −0.767 残る**。

2 位に入ったのは通説外の**『エピノミス』**だった。『法律』の続編とも言われる篇である
(今回の測定は真贋を判定しない)。

**エリジョンでは説明できない** —— 効果量 −0.77 しかなく、後期群の内側でも開く。
避け方は別のところにある。

詳細は [docs/L5-findings.md](docs/L5-findings.md)。

## L6 でいちばん大事だった規律

**「書いていない」を「無い」に見せない。**

和訳は三層に分けてある。第一層(三十六篇の解題)は完遂、
第二層(ステファヌス一頁ごとの一行要旨)は **53 / 1,752 頁 = 3.0%**。
埋まっているのは「ソクラテスの裁判」三篇である。

充填率は**分子と分母のまま**出す。割合だけを出すと、埋まっていない箇所が
「そこには何も無い」と読まれてしまう。篇ごとにも「何頁中の何頁か」を出し、
要旨の無い篇を開くと「まだ書いていない」と明示する。
検品器にも「充填率が分子と分母で出ているか」を置いた。

要旨は**英訳本文を実際に読んで書いた**。記憶や概説からではない ——
そう書いたものは「たぶんこう書いてある」であって、要旨ではない。

解題の本文には**算用数字を書いていない**。数は画面がデータから出す
(G-07 を散文に適用した)。測り直して数が動いても、文章だけが古く残ることがない。

詳細は [docs/L6-findings.md](docs/L6-findings.md)。

## L7 でいちばん大事だった発見

**画面は全部緑で、字が壊れていた。**

三段リーダーのギリシャ語が ``πολυ` δε` τη`ν`` と出ていた(正しくは πολὺ δὲ τὴν)——
アクセントが次の字の後ろに、独立した点として描かれていた。
データは合成済み符号で正しく、CSS の指定も届いていた。
**指定していた書体が多アクセント(polytonic)の字形を持っていなかった**のが原因で、
ブラウザが字ごとに代替書体へ落ちていた。

六つ実測して、この機で正しく描けたのは **Cambria だけ**だった。
Georgia も Palatino Linotype も Times New Roman も Segoe UI も既定の serif も壊れた。
読み手の機械に何が入っているかは当てにできないので、書体を同梱することにした
(`public/fonts/` に woff2 三つと OFL。**ビルドで外へ取りに行かない** —— N-02)。

問題は**検品が全部緑だった**ことである。高さも横溢れも要素数も JS エラーも異常なし。
検品が見ていたのは**字が置かれた場所**であって、**字の形**ではなかった。

なので、Chrome に直接聞くようにした ——
`CSS.getPlatformFontsForNode` で「この節点を実際に何で描いたか」を取り、
**一節点が単一の書体で描き切られていること**を条件にする。
「大半が正しい」では通さない。一部の字だけ代替に落ちるのが、この故障の壊れ方だからである。
和訳の欄(別書体)を陽性対照に置いて、検査が効いていることを毎回確かめる。

詳細は [docs/L7-findings.md](docs/L7-findings.md)。HC-134 に起票した。

## 構成

```
raw/perseus/     Perseus TEI 72 ファイル(上流コミット a1849c8 で凍結・無加工)
data/curated/    人が書いた台帳(作品メタデータ・上流誤植の補正表)
data/works/      篇ごとの節データ(生成物)
data/index.json  画面①の材料(20KB・コミットする)
data/breath.json 画面②の材料(106KB・コミットする)
data/words.json  画面③の材料(108KB・コミットする)
data/style.json  画面④の材料(8KB・コミットする)
data/japanese.json 画面⑤の材料(40KB・コミットする)
data/reader.json 画面⑥の材料(391KB・希英和の本文・コミットする)
etl/             正規化器・発話交替の検出器・語形の照合・較正・調査スクリプト
app/ lib/        Next.js(静的出力)と図の幾何
tests/           Python 側の検査(T-001〜T-016 / T-201〜T-217)
tests-js/        図とフッタ規則の検査(T-101〜T-128 / T-301〜T-314 / T-401〜T-413 / T-501〜T-513 / T-601〜T-611 / T-701〜T-716)
harness/         実ブラウザ検品・フッタ判定規則・字種検査
public/fonts/    同梱の EB Garamond(希語用・OFL 1.1)。ビルドで外へ取りに行かない
docs/            ループごとの所見
```

`data/curated/` には**人が書いた台帳**を置く —— 作品メタデータ、上流誤植の補正表、
そして**語形の採否台帳**(`word-ledger.json`)・**解題**・**頁ごとの要旨**。
コードは台帳を当てるだけで、判断も文章も作らない。

## 使い方

```bash
python etl/normalize.py       # raw/perseus → data/works + data/index.json
python etl/calibrate_turns.py # 発話交替の検出器を較正する(較正 14 篇 / 検証 13 篇)
python etl/build_turns.py     # → data/turns.json + data/breath.json
python etl/audit_words.py     # 語形の採否台帳を両方向で検算する
python etl/build_words.py     # → data/words.json
python etl/test_style_predictions.py  # 宣言した予測と突き合わせる
python etl/build_style.py     # → data/style.json
python etl/build_japanese.py  # 解題と要旨の検算 → data/japanese.json
python -m pytest -q           # 検査
python harness/text_hygiene.py

npm install
npm run dev                 # 開発サーバ
npm run verify              # 型検査 + vitest + 静的ビルド + 実ブラウザ検品
```

`npm run verify` は 390 / 768 / 1280 px の 3 幅 × 6 画面で実際にページを描かせ、
横溢れ・縦の伸びすぎ・固定フッタの高さと逃げ・ラベルの切れ・
目盛りと格子の本数一致・面グラフの中身・升目の段数を測る。
さらに**節への直リンク 7 件(壊れた住所 4 件を含む)**と、
**希語を実際に何の書体で描いたか**(CDP・和訳欄が陽性対照)を見る。
**検品器自身の陽性対照(壊れ方 31 通り)を先に通してから**走査に入る。

```bash
npm run deploy       # Vercel 本番へ(CLI 運用)
npm run smoke:prod   # 本番 URL に対して同じ検品を掛ける
```

**手元の出荷物検査とは別に、本番を引く検品を持つ。** 配信の Content-Type や反映漏れは
ビルド生成物のどこにも書かれておらず、実際に取得するまで存在しない。
