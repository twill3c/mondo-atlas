# L10 の記録 —— リーダーを篇ごとに分けた

loop_016。目標は「リーダーを篇ごとの頁に分ける(N-03)」。
L9 で自分の書いた宿題である —— 四篇目を載せるなら、まずここから。

## 1. なぜ分けたか

分ける前、`/read/` は三篇の本文をまるごと埋め込んでいた。

| | 圧縮前 | 配信 |
|---|---|---|
| `/read/`(三篇まとめて) | 544 KB | 153 KB |

読み物の本文なので絶対量としては許せる。問題は**増え方**だった ——
篇を足すたびに全員の負担が増える。メノン一篇で約 920 KB、
全 36 篇なら圧縮しても数メガバイトになる。N-03(1 篇単位で読み込む)に反していた。

## 2. 分けたあと

| 道筋 | 圧縮前 | 配信 |
|---|---|---|
| `/read/`(目次) | **17 KB** | **5 KB** |
| `/read/euthphr/` | 166 KB | 51 KB |
| `/read/ap/`(いちばん重い篇) | 279 KB | 91 KB |
| `/read/crit/` | 144 KB | 46 KB |

**いちばん重い頁が 544 KB → 279 KB。**
そして篇を足しても、どの頁も重くならない。

目次は**本文を持たない**。これが分割の意味そのものなので、
T-722 が `index.json` の大きさと `sections` の不在を直接見ている。

## 3. 動的ルートにしなかった

`app/read/[work]/page.tsx` の一枚で済ませたくなるが、**静的書き出しでは逆効果**である。
`generateStaticParams` で三頁を書き出しても、その一枚のモジュールが
三篇ぶんの JSON を import することになり、束が分かれない。

だから**篇ごとに薄い頁ファイルを置いた**。

```tsx
import work from "@/data/reader/Crit.json";
export default function Page() { return <WorkPage work={work as unknown as ReaderWork} />; }
```

篇を足すのに三つの手当てが要る ——
`INCLUDE` / `data/reader/<略号>.json` / `app/read/<slug>/page.tsx`。
**手当てが増えるのは良くない**ので、忘れたら落ちる検査を置いた(T-721)。
目次に載る篇には実在する頁と本文ファイルが対応すること、
そして**逆向きに**、頁だけあって目次に無いものは残骸として撃つこと。

対照も確かめた。`app/read/zzz/` を作ってテストを走らせ、
「app/read/zzz/ は目次に無い」で落ちることを見てから消した。

## 4. いちばん気を遣ったのは、壊さないこと

`?loc=Crit.43a` は**既に配ってしまった住所**である。
画面の断り書きにも、公開した解説アーティファクトにも載せた。
分割で古いリンクを壊すのは、この種の作業でいちばん起こりやすい事故である。

だから目次が受け口を兼ねる。`/read/?loc=Crit.43a` を開くと、
形の検査を通ったものだけ `/read/crit/?loc=Crit.43a` へ送る。

検品は**実ブラウザで 11 通り**を走らせる。

| 道筋 | 期待 |
|---|---|
| `/read/crit/?loc=Crit.51c` 他 3 件 | その節を含む頁が開き、焦点が画面内に来る |
| `/read/?loc=Crit.51c` `/read/?loc=Ap.38b` | **目次が篇の頁へ送る** |
| `/read/crit/?loc=Ap.17a` | 別の篇の住所なので何もしない(既定の頁) |
| `/read/?loc=<script>` `?loc=Crit.99z` `?loc=Rep.327a` | **目次に留まる**(送り直さない) |
| `/read/crit/`(住所なし) | 既定の頁 |

最後から二行目が要る。壊れた住所で篇の頁へ送ってしまえば、
形の検査を素通りさせたことになる —— **正例だけ並べても、そこは見えない。**

## 5. 検品器の期待値を「道筋の数」から切り離した

画面の切り替え(Nav)の数を、これまで検品の道筋の数(`PAGES.length`)から取っていた。
篇の頁は Nav に出ないので、この二つはもう別物である。

`app/Nav.tsx` の中身を実測して数えるようにした。
実測が壊れたとき(5 個未満しか読めないとき)は、
不合格ではなく**検品器自身の異常**(終了コード 2)として止める。
同様に、篇ごとの期待値(頁の束の数・初手に開く頁の節数)も
`data/reader/index.json` から導く —— 篇を足せば検品の対象も自動で増える。
