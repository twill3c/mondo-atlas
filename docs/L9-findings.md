loop_013。目標は「ソクラテスの弁明 全 125 節を完訳する(F-12 の三本目)」。

全集に対しては **254 / 8,559 節 = 2.97%**。
SPEC F-12 の初回対象「ソクラテスの裁判 三篇(17,988 語)」は、これで完了である。

弁明は対話ではなく法廷での一人語りなので、鉤括弧の応酬が使えない。

節の切れ目は相変わらず文の途中に落ちる。35e は
「私は嘆いてはいない、アテナイの人々よ、」の 19 字で終わり、
続きは 36a の頭にある。**原文がそこで切れているから、訳もそこで切る。**

## 2. 完訳したせいで、対照が一つ死んだ

三篇とも完訳になった瞬間、**実データから「未訳」が消えた**。

これは静かに困る。T-703(完訳の篇は完訳と出る)には、これまで
「まだ訳していない弁明が完訳と出ないこと」という対照が付いていた。
その対照の主語が無くなったのである。

対照が無いまま T-703 だけを残すと、
**`complete` を常に `true` と答える実装でも緑になる。**
完訳を積み上げた結果、検査が弱くなるという妙なことが起きる。

三つ考えた。

1. 未訳の篇(メノン)をリーダーに足して、実データに未訳を残す
2. 対照を**合成した篇**で書く
3. 対照を諦める

**2 を選んだ。** 1 は下の理由で採れず、3 は論外である。
合成した篇(2 節・うち 1 節が未訳)で `isUntranslated` と `progress` を撃つ
T-717 を足した。実データが未訳を持たなくなっても、判定そのものは検査され続ける。

> 実データが「良い状態」に到達すると、悪い側を撃つ対照は主語を失う。
> **そのとき対照を消すのではなく、合成に移す。**

## 3. なぜ四篇目を足さなかったか —— 測ったから

「メノンを足せば未訳が実データに戻る」は魅力的だったが、先に重さを測った。

| | |
|---|---|
| `out/read/index.html`(三篇) | **544 KB** |
| gzip | 177 KB |
| **本番が実際に配っている量** | **153 KB** |
| メノン(151 節)を足すと | 約 920 KB(配信 約 260 KB) |

リーダーは本文をページに直に埋め込んでいる。
**篇を足すほど転送量が増える作りで、全 36 篇を一枚に載せることはできない。**
N-03(作品ごとに分割し 1 篇単位で読み込む)は、この画面では守られていない。

だから四篇目は足さなかった。足すときは**篇ごとにページを分ける**ところから始める。
この判断の根拠を T-718 に固定した —— 本文の総字数が閾値を超えたら落ちる。
「そのうち重くなる」という感想ではなく、**次に触る人が数から判断できる**ようにした。
